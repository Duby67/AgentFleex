# Участие в разработке

[English](../CONTRIBUTING.md) · **Русский**

## Issues

Сообщайте об ошибках и предлагайте возможности через формы issue. Об уязвимостях сообщайте
приватно, как описано в [SECURITY.md](SECURITY.md), и никогда — в публичном issue.

## Окружение

Корень репозитория — это корень плагина; скиллы лежат в `skills/`, хуки — в `hooks/`, тесты — в
`tests/`. Манифесты: `.claude-plugin/` и `.codex-plugin/` (плагин),
`.claude-plugin/marketplace.json` и `.agents/plugins/marketplace.json` (маркетплейсы).

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/), затем выполните
`uv sync --locked`: команда создаст игнорируемую `.venv` из `pyproject.toml` и `uv.lock`. Один раз
установите хук коммита командой `uv run --locked pre-commit install`. Добавляйте зависимости
разработки через `uv add --dev`, запускайте Python-команды через `uv run --locked`. Настройки Python
для VS Code по умолчанию указывают на `.venv`; если интерпретатор уже был выбран, укажите его через
`Python: Select Interpreter`.

Чтобы попробовать изменения скиллов, запустите Claude Code с `claude --plugin-dir .`; в Codex
переустановите плагин из локального маркетплейса.

## Проверки

- Тесты: `uv run --locked python -m unittest discover -s tests`. CI гоняет их на Linux, macOS и
  Windows с Python 3.9 и последним Python, с Universal Ctags и без.
- Всё остальное: `uv run --locked pre-commit run --all-files`, хуки из
  [.pre-commit-config.yaml](../../.pre-commit-config.yaml): Ruff, mypy, ShellCheck, markdownlint,
  yamllint, гигиена файлов и проверка версии.

## Ветки

- `develop`, ветка по умолчанию, — рабочая ветка: каждая ветка начинается от неё, и каждый pull
  request направляется в неё. В ней только законченные изменения, поэтому её можно выпустить в любой
  момент.
- `main` хранит релизы: в неё сливается только `develop`.
- Ветки задач называются `<type>/<description>`: описание из двух–пяти слов строчными буквами
  через дефис, в начале можно указать номер issue (`fix/42-hook-unicode-paths`). Типы:

  | Тип | Назначение |
  | --- | --- |
  | `feat/` | Новое поведение |
  | `fix/` | Исправление ошибки |
  | `docs/` | Только документация |
  | `refactor/` | Изменение кода без изменения поведения |
  | `test/` | Только тесты |
  | `ci/` | CI и workflow релиза |
  | `chore/` | Зависимости, инструменты и прочее сопровождение |
  | `claude/`, `codex/` | Ветки, созданные Claude Code или Codex в облаке |
  | `dependabot/` | Обновления зависимостей, созданные Dependabot |

## Pull requests

- Одно изменение на pull request в `develop`, заголовок называет изменение.
- Проверки проходят после последнего коммита.
- Заметные пользователю изменения записываются в раздел `## Unreleased` файла
  [CHANGELOG.md](CHANGELOG.md) как решённая проблема и итоговое поведение.
- Документы для людей пишутся на английском и переводятся на русский в `docs/ru/`; во время
  разработки перевод может отставать с пометкой об этом и синхронизируется перед релизом.

## Версии и релизы

Версии следуют [семантическому версионированию](https://semver.org/lang/ru/). Пока версия `0.x`,
минорный номер отмечает изменённое или удалённое поведение скиллов и хуков, а патч — исправления и
дополнения. Установленные плагины обновляются только при повышении версии. У `develop` нет своей
версии: в ней остаётся последняя выпущенная, пока релиз её не повысит.

Каждое слияние в `main` — это релиз, его делает мейнтейнер:

1. В `develop` повысьте `project.version` в `pyproject.toml` выше последнего тега, затем выполните
   `uv lock` и команду синхронизации, чтобы обновить оба манифеста плагина:

   ```bash
   uv run --locked python skills/fleex-repo/scripts/release.py \
     --manifest .claude-plugin/plugin.json --manifest .codex-plugin/plugin.json sync
   ```

2. Переименуйте `## Unreleased` в
   `## [x.y.z](https://github.com/Duby67/AgentFleex/releases/tag/x.y.z)` во всех changelog,
   оставьте над ним пустой `## Unreleased` и синхронизируйте переводы.
3. Запушьте `develop`; CI запустит тесты и pre-commit.
4. Откройте pull request из `develop` в `main`. CI покажет результаты `develop`, отклонит pull
   request из любой другой ветки и добавит проверку релиза
   ([release.py](../../skills/fleex-repo/scripts/release.py)): оба манифеста совпадают с версией,
   `## Unreleased` пуст, во всех changelog есть раздел версии с одинаковыми заголовками, а версия
   выше последнего тега.
5. Слейте через **Create a merge commit**. Squash и rebase переписывают коммиты, и `main` с
   `develop` расходятся.
6. Пуш в `main` повторяет проверку релиза, ставит тег версии и публикует её как последний релиз
   GitHub с заметками из её раздела, где каждый перевод свёрнут под названием языка.

Ошибка в релизе исправляется в `develop` и выходит со следующей патч-версией.
