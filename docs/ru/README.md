# AgentFleex

[English](../../README.md) · **Русский**

Плагин для Claude Code и Codex, который держит `AGENTS.md`, скиллы репозитория и документацию
короткими и согласованными.

## Установка

Claude Code:

```bash
claude plugin marketplace add Duby67/AgentFleex
claude plugin install agentfleex@agentfleex
```

Codex:

```bash
codex plugin marketplace add Duby67/AgentFleex
codex plugin add agentfleex@agentfleex
```

## Что плагин настраивает в репозитории

| Путь | Назначение |
| --- | --- |
| `AGENTS.md` | Единственный файл правил и единственная точка входа; Codex читает его сам |
| `.claude/CLAUDE.md` | Только для Claude Code: одна строка `@../AGENTS.md`, которая импортирует тот же файл |
| Источник скиллов | Единая папка `skills/` в корне репозитория, если есть проектные скиллы |
| `.agents/skills`, `.claude/skills` | Относительные симлинки на источник, только для используемых агентов: Codex читает `.agents/skills`, Claude Code — `.claude/skills` |

Папка агента (`.claude/`, `.cursor/`) создаётся, только если репозиторий использует этого агента,
и игнорируется Git. Локальные импорты и симлинки остаются на диске; необходимые метаданные
распространения плагина сохраняются в Git через явное исключение.

Общие скиллы `fleex-*` приходят из плагина и не копируются в репозиторий. Оба клиента находят скиллы
по полю `description`, поэтому `AGENTS.md` не нужна таблица маршрутизации.

Файлы для агентов (`AGENTS.md`, скиллы, документация для агентов) пишутся на английском.
Документация для людей тоже пишется на английском. Переводы появляются, только когда их просит
пользователь или `AGENTS.md` уже перечисляет языки, и все лежат в `docs/<код>/`: `README.md` — как
`docs/ru/README.md`, страница из `docs/` — по тому же пути внутри `docs/ru/`; в каждом файле набора
под заголовком стоит одна строка-переключатель языка. `AGENTS.md` перечисляет языки
(`translated to: ru`); удаление языка удаляет его файлы и больше ничего не переносит. В чате агент
отвечает на языке вопроса.

## Хуки

Плагин поставляет `hooks/hooks.json`, который загружают и Claude Code, и Codex:

- перед тем как агент остановится, проверки fleex-hygiene, принимающие файлы, запускаются на
  файлах, изменённых относительно `HEAD`, по одному разу на каждое состояние этих файлов, и их
  ошибки возвращают агента исправлять. Линтеры используют конфигурацию самого репозитория, которая
  может выполнять код, поэтому агент сначала спрашивает вас, разрешить ли их в этом репозитории;
  ответ хранится в данных плагина, а не в репозитории, и новый набор инструментов спрашивается
  заново. `git diff --check` запускается без вопроса;
- в Claude Code первое чтение целиком файла длиннее 400 строк отклоняется, а агент получает его
  outline из fleex-index и читает только нужные диапазоны; повторное чтение читает файл целиком.

Хукам нужен `python3` или `python` в `PATH`. Codex запускает хук плагина только после того, как
вы одобрите его в `/hooks`.

## VS Code

Попросите агента подготовить рабочее пространство VS Code под задачу: скилл `fleex-vscode` выбирает
наборы из `skills/fleex-vscode/assets/` по задаче и файлам проекта и сливает их рекомендации
расширений и настройки в `.vscode/` проекта, которая остаётся в игноре Git. На новой машине весь
набор ставится разом: `Extensions: Show Recommended Extensions`, затем кнопка Install Workspace
Recommended Extensions. Агент может посоветовать другие расширения под задачу, но не предлагает
удалять ваши и сам ничего не устанавливает. Только если вы попросите синхронизировать установленные
расширения с рекомендациями, он ставит недостающие, а затем отдельным шагом, после вашего
подтверждения, удаляет лишние.

| Набор | Когда |
| --- | --- |
| `default` | Всегда: редактор, Git, Markdown, YAML, TOML, EditorConfig |
| `personal` | Всегда: тема и раскладка интерфейса |
| `python` | Проекты на Python |
| `cpp` | Проекты на C и C++ |
| `infrastructure` | Docker, CI, shell-скрипты, удалённые хосты |
| `tools` | REST, draw.io, hex, CSV, XML, Inno Setup, npm |

Горячие клавиши и настройки уровня приложения или машины работают только в профиле пользователя;
держите их там, например через Settings Sync.

## Устройство репозитория

Корень репозитория — это корень плагина; скиллы лежат в `skills/`, хуки — в `hooks/`. Манифесты:
`.claude-plugin/` и `.codex-plugin/` (плагин), `.claude-plugin/marketplace.json` и
`.agents/plugins/marketplace.json` (маркетплейсы). Чтобы попробовать изменения скиллов, запустите
Claude Code с `claude --plugin-dir .`; в Codex переустановите плагин из локального маркетплейса.
Тесты скриптов скиллов и хуков лежат в `tests/` и запускаются командой
`uv run --locked python -m unittest discover -s tests`; CI гоняет их на Linux, macOS и Windows с Python 3.9 и
последним Python, с Universal Ctags и без. Все остальные проверки — хуки pre-commit в
[.pre-commit-config.yaml](../../.pre-commit-config.yaml): Ruff, mypy, ShellCheck, гигиена файлов и
проверка версии. Установите [uv](https://docs.astral.sh/uv/getting-started/installation/), затем
выполните `uv sync --locked`: команда создаст игнорируемую `.venv` из `pyproject.toml` и `uv.lock`.
Добавляйте зависимости разработки через `uv add --dev`, запускайте Python-команды через
`uv run --locked`. Установите хук коммита командой `uv run --locked pre-commit install`;
проверяйте все файлы через `uv run --locked pre-commit run --all-files`.
Набор настроек Python для VS Code по умолчанию указывает на `.venv`; если интерпретатор уже был
выбран, укажите его через `Python: Select Interpreter`.

Источник версии — `project.version` в `pyproject.toml`. После изменения выполните `uv lock`
и `uv run --locked python .github/scripts/release.py sync`, чтобы обновить оба манифеста плагина.
Установленные плагины подхватывают изменения только после повышения версии.
Изменения записываются в раздел `## Unreleased` файла
[CHANGELOG.md](CHANGELOG.md); при выпуске он переименовывается в версию. Работа идёт в `develop`, и
каждое слияние в `main` — это релиз. [release.py](../../.github/scripts/release.py) проверяет, что в
обоих манифестах версия x.y.z совпадает с TOML, что в `CHANGELOG.md` есть её раздел и что у переводов те же
заголовки. Пуш в `develop` запускает тесты и pre-commit; pull request в `main` показывает их
результаты для своего последнего коммита и добавляет проверку релиза: пустой `## Unreleased`,
заметки во всех changelog и версию выше последнего тега. Сделайте эти проверки обязательными для
`main` в настройках защиты веток, чтобы `develop` с ошибками нельзя было слить. Пуш в `main`
повторяет проверку релиза, ставит тег версии и публикует её как последний релиз с заметками из её
раздела, а разделы переводов свёрнуты под названием языка. Сообщения об уязвимостях:
[SECURITY.md](../../.github/SECURITY.md). Лицензия — [MIT](../../LICENSE).

## Экономия токенов

Главная статья расходов — файлы, которые агент читает часто, и прежде всего `AGENTS.md`: он
попадает в каждый запрос к модели. Поэтому:

- `AGENTS.md` содержит только то, что нужно в каждой задаче и что агент не выведет сам: что это за
  проект, жёсткие инварианты, указатели на владельцев;
- всё, что файл уже подразумевает или агент и так знает, удаляется;
- детали задач живут в скиллах: в каждый запрос попадает только их `description`, а тело читается
  по необходимости;
- каждый факт живёт в одном месте, всё остальное ссылается на него.

Каждый скилл владеет своими файлами: [fleex-agents](../../skills/fleex-agents/SKILL.md) владеет
`AGENTS.md`, `.claude/CLAUDE.md` и единым каталогом общих правил;
[fleex-skills](../../skills/fleex-skills/SKILL.md) — скиллами, их подключением и ссылками на лучшие
практики; [fleex-docs](../../skills/fleex-docs/SKILL.md) — документацией для людей;
[fleex-i18n](../../skills/fleex-i18n/SKILL.md) — её переводами;
[fleex-index](../../skills/fleex-index/SKILL.md) — скрипт навигации без зависимостей (map, outline,
show, find, refs), чтобы агенты читали только нужные строки;
[fleex-hygiene](../../skills/fleex-hygiene/SKILL.md) находит и запускает настроенные в репозитории
линтеры, форматтеры и проверки типов, чтобы каждое изменение сохраняло единый стиль.
[fleex-todo](../../skills/fleex-todo/SKILL.md) владеет бэклогом `TODO.md` с проверенными находками и
запланированной работой. Существующая
конфигурация всегда в приоритете; если её нет, действуют настройки плагина по умолчанию из
`skills/fleex-hygiene/assets/`. Этот репозиторий тоже их использует: `ruff.toml` расширяет
конфигурацию Ruff по умолчанию, а CI передаёт mypy конфигурацию по умолчанию. Правила, однажды
записанные в `AGENTS.md` репозитория, принадлежат его владельцу и не синхронизируются с каталогом.

Каждый `AGENTS.md` получает одну модель веток: `develop` — рабочая ветка, от которой начинаются и в
которую направляются все ветки, форки и PR; `staging` принимает `develop` для развёртывания на
тестовом сервере, а её баги исправляются в `develop`; `main`, ветка по умолчанию, принимает только
проверенный `staging` и хранит релизы. Репозиторий сохраняет свои названия веток, если их задал
пользователь.
