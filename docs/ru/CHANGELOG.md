# Changelog

[English](../CHANGELOG.md) · **Русский**

## Unreleased

- Тесты ограничивают всегда загружаемый контекст (`AGENTS.md` и описания автоматически вызываемых
  скиллов), проверяют, что `check.sh` сообщает о каждом виде ошибок, и сравнивают с ним
  `check.ps1` там, где установлен PowerShell.
- markdownlint и yamllint входят в настройки гигиены по умолчанию: `fleex-hygiene` предлагает их с
  конфигурациями плагина и закреплёнными версиями репозиториям, где ни один не настроен, а базовый
  шаблон pre-commit их содержит. Этот репозиторий запускает оба в pre-commit.
- Добавлен скилл `fleex-repo` с явным вызовом: он проверяет и настраивает служебные файлы и
  параметры репозитория GitHub (LICENSE, `.gitignore`, `.gitattributes`, заготовки SECURITY и
  CONTRIBUTING, шаблоны issue и PR, Dependabot, CI) и механизм релизов по
  шаблонам из этого репозитория; GitLab вне охвата.
- `release.py` перенесён в `fleex-repo` и работает в любом репозитории: версия берётся из
  `pyproject.toml`, `package.json` или `VERSION`, манифесты передаются через `--manifest`, а
  changelog — `docs/CHANGELOG.md` или `CHANGELOG.md`.
- `fleex-hygiene` снова загружается автоматически, по-прежнему запускается только по запросу или
  перед PR или merge, а руководство по настройке хранит в справочнике; добавлены шаблоны
  `.editorconfig` и базового pre-commit. В этом репозитории появился `.editorconfig`.
- `staging` входит в модель веток только для репозиториев с деплоем на тестовый сервер.
- `SECURITY.md` перенесён в `docs/` с русским переводом, а его охват приведён к текущим хукам и
  скриптам.
- README описывает плагин как инструмент настройки репозиториев целиком, с таблицей скиллов и
  устройством репозитория.
- `fleex-hygiene` больше не запускает Poetry для поиска окружения проекта, потому что Poetry может
  установить плагины, объявленные в репозитории; проверяется только `.venv` внутри проекта.
- `fleex-hygiene` завершается с понятной ошибкой вместо вывода команды с путём, содержащим `%`,
  который cmd раскрыл бы в Windows.
- Ruff и mypy по умолчанию запускаются через `uvx` с закреплёнными версиями, совпадающими с хуками
  pre-commit этого репозитория, поэтому результаты больше не меняются с новыми релизами.
- На GitHub включены приватные сообщения об уязвимостях.
- `CHANGELOG.md` и `TODO.md` перенесены в `docs/`; проверка релиза читает `docs/CHANGELOG.md`, а
  `fleex-docs` создаёт новый бэклог как `docs/TODO.md`.
- Добавлен `docs/CONTRIBUTING.md`: окружение, проверки, именование веток (`<type>/<description>`),
  pull request, семантическое версионирование и шаги релиза; README ссылается на него вместо
  описания разработки.
- Добавлены формы issue для ошибок и предложений, шаблон pull request и ссылка для приватных
  сообщений об уязвимостях; пустые issue отключены.
- CI отклоняет pull request в `main` из любой ветки, кроме `develop`.
- Каталог правил `AGENTS.md` задаёт имена веток задач `<type>/<kebab-description>`.
- `fleex-vscode` запускается только явным вызовом, поэтому его описание больше не загружается в
  каждый запрос Claude Code и Codex.
- Скилл `fleex-todo` стал справочником `fleex-docs`, читаемым только при правке `TODO.md`.
- Переводы перенесены из скилла `fleex-i18n` в `fleex-docs` как справочник, читаемый по
  необходимости; переводы по-прежнему выполняются только по запросу.
- Убраны автоматические проверки при завершении ответа и запросы согласия; гигиена запускается по
  запросу или перед PR или merge, переводы — только по запросу, отставание переводов при разработке
  допустимо.
- Read-хук считает строки блоками и использует атомарные маркеры файлов сессии в приватных данных
  плагина; параллельные чтения больше не теряют состояние и не отклоняют один файл повторно.
- Редкие подзадачи размещаются в references связанных скиллов; отдельные скиллы сохраняют разные
  условия вызова.
- Источник версии перенесён в `pyproject.toml`; `release.py sync` обновляет оба манифеста плагина,
  pre-commit и CI отклоняют несовпадающие версии.
- Добавлено окружение разработки под управлением uv с lock-файлом, `.venv` и командами CI;
  uv используется по умолчанию для Python-проектов, настройки Python в VS Code указывают на `.venv`.

## [0.3.3](https://github.com/Duby67/AgentFleex/releases/tag/0.3.3)

- Исправлено падение вывода заметок о релизе с кириллицей на Windows: используется UTF-8.
- Заметки о релизе теперь описывают решённые проблемы и итоговое поведение без учёта операций
  со списком задач.
- Добавлен скилл `fleex-vscode`: рекомендации расширений и настройки VS Code по наборам,
  сливаемые в игнорируемую `.vscode/` проекта; он может посоветовать другие расширения, не
  предлагает удалять установленные и по запросу синхронизирует установленные расширения с наборами,
  удаляя лишние отдельным шагом после подтверждения.
- `.vscode/settings.json` больше не отслеживается; `.vscode/` в игноре.
- В каталог правил `AGENTS.md` добавлена модель веток: `develop` для работы, `staging` для
  тестирования, `main` для релизов.
- Разработка перенесена в `develop`: пуш в неё запускает тесты и pre-commit, pull request в
  `main` добавляет проверку релиза, а пуш в `main` выпускает релиз.
- Ruff, mypy, ShellCheck и проверки файлов работают как хуки pre-commit; `fleex-hygiene` делает
  pre-commit средством гигиены каждого репозитория и проверяет перечисленный в нём инструмент только
  через него.
- Каждое слияние в `main` — релиз: CI отклоняет версию не выше последнего тега, а
  `.github/scripts/release.py` содержит проверки версии и changelog для CI и pre-commit.
