## [0.4.0](https://github.com/Duby67/AgentFleex/releases/tag/0.4.0)

- Добавлен скилл `fleex-repo` с явным вызовом: он проверяет и настраивает служебные файлы и
  параметры репозитория GitHub (LICENSE, `.gitignore`, `.gitattributes`, заготовки SECURITY и
  CONTRIBUTING, формы issue и шаблон PR, Dependabot, CI, приватные сообщения об уязвимостях) и его
  релизы по шаблонам из этого репозитория.
- `fleex-repo` содержит `release.py` для любого репозитория: версия берётся из `pyproject.toml`,
  `package.json` или `VERSION`, файлы `--manifest` синхронизируются, а CI отклоняет pull request в
  `main` из любой ветки, кроме источника релиза, затем ставит тег на каждое слияние в `main` и
  публикует его с заметками из `docs/CHANGELOG.md`.
- В каждый запрос загружается меньше описаний скиллов: переводы и бэклог `TODO.md` стали
  справочниками `fleex-docs` вместо `fleex-i18n` и `fleex-todo`, а `fleex-vscode` запускается только
  явным вызовом. Тесты ограничивают размер `AGENTS.md` и автоматически загружаемых описаний.
- `fleex-hygiene` загружается автоматически, но запускается только по запросу или перед PR или
  merge; автоматических проверок при завершении ответа и запросов согласия больше нет. Руководство
  по настройке стало справочником с шаблонами `.editorconfig` и базовой конфигурации pre-commit.
- markdownlint и yamllint присоединились к Ruff, mypy и ShellCheck в настройках гигиены по
  умолчанию, а инструменты по умолчанию запускаются через `uvx` или `npx` с закреплёнными версиями,
  поэтому результаты больше не меняются с новыми релизами.
- `fleex-hygiene` больше не запускает Poetry, который может установить объявленные в репозитории
  плагины, для поиска окружения проекта и завершается с понятной ошибкой вместо вывода команды с
  путём, содержащим `%`, который cmd раскрывает в Windows.
- Python-репозитории по умолчанию используют uv с закоммиченным `uv.lock` и игнорируемой `.venv`;
  настройки Python для VS Code указывают на `.venv`.
- Модель веток добавляет `staging` только для репозиториев с деплоем на тестовый сервер, а ветки
  задач называются `<type>/<kebab-description>`.
- Документация для людей, кроме README, лежит в `docs/` (`CHANGELOG.md`, `CONTRIBUTING.md`,
  `SECURITY.md`, `TODO.md`), каждый файл переведён на русский; новые бэклоги создаются как
  `docs/TODO.md`.
- Read-хук считает строки блоками ограниченного размера и хранит атомарные маркеры файлов в
  приватных данных плагина, поэтому параллельные чтения больше не теряют состояние и не отклоняют
  один файл дважды.

## [0.3.3](https://github.com/Duby67/AgentFleex/releases/tag/0.3.3)

- Исправлено падение вывода заметок о релизе с кириллицей на Windows: используется UTF-8.
- Заметки о релизе теперь описывают решённые проблемы и итоговое поведение без учёта операций
  со списком задач.
- Добавлен скилл `fleex-vscode`: рекомендации расширений и настройки VS Code по наборам,
  сливаемые в игнорируемую `.vscode/` проекта; он может посоветовать другие расширения, не
  предлагает удалять установленные и по запросу синхронизирует установленные расширения с наборами,
  удаляя лишние отдельным шагом после подтверждения.
- `.vscode/settings.json` больше не отслеживается; `.vscode/` в игноре.
- В каталог правил `AGENTS.md` добавлена модель веток: `develop` для работы, `staging` для
  тестирования, `main` для релизов.
- Разработка перенесена в `develop`: пуш в неё запускает тесты и pre-commit, pull request в
  `main` добавляет проверку релиза, а пуш в `main` выпускает релиз.
- Ruff, mypy, ShellCheck и проверки файлов работают как хуки pre-commit; `fleex-hygiene` делает
  pre-commit средством гигиены каждого репозитория и проверяет перечисленный в нём инструмент только
  через него.
- Каждое слияние в `main` — релиз: CI отклоняет версию не выше последнего тега, а
  `.github/scripts/release.py` содержит проверки версии и changelog для CI и pre-commit.

## [0.3.2](https://github.com/Duby67/AgentFleex/releases/tag/0.3.2)

- Добавлен скилл `fleex-todo` для бэклога `TODO.md`.
- Добавлены `CHANGELOG.md`, `.github/SECURITY.md` и `.gitattributes`.
- `VERSION` и `version.py` заменены проверкой версий манифестов в pre-commit.
- CI выпускает релиз для версии манифеста, у которой ещё нет релиза на GitHub, с заметками из
  `CHANGELOG.md`; изменения ждут релиза в `## Unreleased`, а переводы свёрнуты под названиями
  языков.
- Исправлена проверка скиллов, падавшая на чистом клоне из-за закоммиченных метаданных плагина в
  `.agents/` и на macOS, где bash 3.2 принимал `./skills` за путь скиллов агента.
